# 存储插件与文件模块（简历写法）

## 一句话版本
主导云盘系统存储插件化改造，解耦文件元数据与对象存储实现（Local/S3），落地文件模块插件强相关 CRUD（预签名下载、对象读取、硬删除补偿），提升可扩展性与可运维性。

## 可直接放简历的项目描述（中级）
- 设计并实现存储插件体系（Local/S3），以统一 `Store` 能力抽象上层文件服务，屏蔽底层 SDK 差异。
- 完成文件模块与存储插件对齐：下载 URL 统一走插件预签名，预览内容统一走插件读流接口。
- 重构永久删除链路为“元数据删除 + 对象删除”双阶段，输出删除报告（成功/失败对象数、失败 key），支持后续补偿清理。
- 在不改前端协议的前提下实现平滑升级，后端编译与接口行为保持稳定。

## 可直接放简历的项目描述（高级）
- 负责存储域工程化改造：构建插件注册/解析/能力协商机制，将对象读写、预签名、删除能力标准化，支持 Local 与 S3 无缝切换。
- 在文件服务引入面向接口依赖（StorageGateway），将插件能力收敛为最小集合，降低模块耦合并提升可测试性。
- 设计硬删除一致性策略：优先删除元数据保证用户视图，再执行对象删除并返回结构化报告，形成“业务可用 + 运维可追踪”的折中方案。
- 形成面向多租户/多空间的扩展边界：认证层识别用户身份，上层通过空间上下文选择存储配置，避免 token 绑定工作空间导致的频繁重签。

## 量化指标写法建议（你可替换真实数据）
- 存储后端接入成本从 N 天降到 0.5~1 天（新增插件仅实现统一接口）。
- 文件删除链路问题定位时长降低 xx%（新增删除报告与失败 key）。
- 预签名下载失败回退链路覆盖率提升到 xx%。
